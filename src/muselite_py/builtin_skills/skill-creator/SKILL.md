# Skill Creator

为 MuseLite 创建可复用的任务流程。尊重用户指定的目标、范围和输出；缺少关键条件时询问用户，能够从对话或工具结果推断的条件自行整理。

## 创建流程

1. 确认技能解决什么任务、何时使用，以及实际可用的工具。查看当前可用技能，避免同名或重复能力。
2. 确定一个不超过 64 字符的小写英文名称，用连字符连接单词。目录名称和 `name` 必须一致。
3. 编写 `SKILL.md`，以 YAML 元数据开始，包含 `name` 和 `description`。描述同时说明功能和触发场景；正文写必要步骤、输入输出、关键判断条件及真实限制。中文说明可直接使用。
4. 只有明确需要时添加支持文件：详细资料放 `references/`，确定性处理代码放 `scripts/`，模板和输出资源放 `assets/`。正文说明何时读取每个参考文件及如何使用脚本；避免生成空目录、占位文件或重复文档。
5. 使用 `skill_create` 一次提交完整 `SKILL.md` 和资源文件。成功后技能自动开启，并立即出现在本轮可用目录中。工具报错时修正具体问题；同名技能不能覆盖，请换名或让用户在设置中的 Skill 页面编辑原技能。
6. 检查工具返回的名称与资源列表。若用户要求立即使用新技能，先调用 `skill_load`，再依照其说明执行。需要验证脚本时使用 Android 的 `shell_execute`；桌面预览不能运行 Linux 脚本，不要宣称已经验证。
7. 简要告诉用户创建了什么、如何触发，以及可在“设置 → Skill”关闭或编辑。

## 编写原则

- Skill 提供工作方法，不增加工具或系统权限。只使用当前系统实际提供的工具，不虚构工具、连接器或接口。
- 名称与描述会先进入模型上下文；完整说明在加载技能时读取，参考文件再按需读取。保持主说明简洁，避免把大量参考资料复制进正文。
- 相对文件路径以 `skill_load` 返回的 `base_path` 为根；脚本通过已有 `shell_execute` 执行。不要硬编码请求快照路径或设备私有目录。
- `base_path` 是本轮任务的临时输入快照。脚本的持久输出应写入 `/var/muselite/workspace` 中的其他目录，不能留在快照目录内。
- YAML 字符串包含冒号、特殊字符时正确加引号，或使用 `description: |` 多行形式。
- 不把对话中的 API Key、密码或私人材料复制进可复用技能；使用占位符和用户提供的运行时输入。
- 不以“系统最高优先级”等措辞覆盖系统规则或当前用户要求，不让普通任务自动变成创建技能的请求。

需要工具参数格式或资源编码示例时，读取 [创建接口](references/creation-api.md)。
